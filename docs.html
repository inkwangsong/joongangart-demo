① 카페24 로그인 — 가능

공식 기능이 있습니다

카페24 개발자센터의 “쇼핑몰 회원 인증” 기능입니다. 카페24 회원 정보로 제3의 시스템에서 인증하는 기능이며 OAuth 2.0 방식입니다.

헷갈리기 쉬운 지점 — 카페24에 “SSO·SNS 로그인”이라는 다른 문서가 있는데 방향이 반대입니다. 그건 외부 계정으로 카페24에 로그인하는 기능이고, 우리에게 필요한 건 “쇼핑몰 회원 인증”입니다.

확인할 점내용
회원 식별카페24가 주는 고유 식별자를 기준으로 씁니다. 이메일·아이디는 바뀔 수 있어 기준이 될 수 없습니다
탈퇴 시기존 쇼핑몰 탈퇴 시 로그인 불가. 이미 구매한 악보를 어떻게 할지 정책 필요
개인정보두 사이트 사업자가 동일한지에 따라 근거가 달라집니다 — 법률 확인
약점카페24 장애 시 우리 사이트도 로그인이 막힙니다. 계정을 하나로 유지하는 이점과 맞바꾼 부분입니다

② 워터마크 PDF — 가능

원본 PDF 위에 구매 정보를 새겨 사본을 만들어 전달합니다. 원본은 나가지 않습니다. 같은 주문은 결과물이 동일하므로 한 번 만들어 저장해두면 재다운로드가 빨라집니다.

③ 구독 모델 — 기술은 가능, 지금은 보류

한국에도 빌링키 방식의 정기결제가 있고, 우리가 쓸 KG이니시스도 지원합니다. 결제를 붙이는 것 자체는 어렵지 않습니다.

H-01
추천 검색어는 사람이 고르고, 인기 검색어는 집계합니다 추천은 “무엇을 앞에 내세울지”라는 영업 판단이고, 인기는 “고객이 무엇을 찾았는지”라는 사실입니다. 추천을 집계로 정하면 절기가 지나도 지난 검색어가 위에 남고, 인기를 손으로 고치면 더 이상 인기가 아닙니다. 둘을 섞지 않습니다.
H-02
추천 검색어에는 노출 기간을 둡니다 성탄 칸타타는 10~12월, 부활절은 2~3월처럼 기간을 정해두면 절기가 바뀔 때마다 지우고 넣을 필요가 없습니다. 기간이 비어 있으면 계속 노출합니다. 고객 화면에는 최대 9개까지 보입니다.
H-03
인기 검색어에는 제외 목록을 둡니다 자동 집계라도 오타, 시험 입력, 다른 업체 이름처럼 올라오면 안 되는 말을 내릴 방법은 있어야 합니다. 목록을 직접 고치는 대신 제외 목록에 넣어 순위에서 빼냅니다.
H-04
홈 화면의 블록은 모두 관리자에서 켜고 끌 수 있어야 합니다 메인 배너만 고정입니다. 나머지는 운영해 보고 안 쓰이면 개발 없이 끌 수 있어야 합니다. 예전에는 ‘절기로 찾기’가 메인 배너에 묶여 끌 수 없었고, ‘컬렉션’은 목록에 아예 없었습니다.

한글 폰트가 첫 번째 관문입니다

PDF 표준 내장 폰트로는 한글을 쓸 수 없습니다. 반드시 폰트 파일을 임베딩해야 하며, 이때 subset: true 옵션이 핵심입니다. 한글 폰트는 4~8MB인데 서브셋을 켜면 실제 사용한 글자만 넣어 30~60KB로 줄어듭니다. 이 옵션을 놓치면 악보 한 장마다 5MB가 붙습니다.

폰트 라이선스도 확인이 필요합니다. 임베딩이 허용된 폰트여야 합니다. Pretendard, 나눔고딕은 OFL 라이선스라 사용 가능합니다.

03구현 흐름과 코드

기본 골격

// 원본 PDF에 구매 정보를 새겨 사본을 만듭니다
import { PDFDocument, rgb, degrees } from 'pdf-lib';
import fontkit from '@pdf-lib/fontkit';

async function stampPdf(originalBytes, order) {
  const pdf = await PDFDocument.load(originalBytes);
  pdf.registerFontkit(fontkit);

  // 한글 폰트 임베딩 — subset 필수 (4MB → 40KB)
  const fontBytes = await fs.readFile('./fonts/Pretendard-Regular.ttf');
  const font = await pdf.embedFont(fontBytes, { subset: true });

  const line1 = `중앙아트 J&A MUSIC · 주문번호 ${order.no}`;
  const line2 = `${order.buyer}님 ${order.copies}부 구매 · 재배포 금지`;

  for (const page of pdf.getPages()) {
    // 페이지 회전과 원점을 반드시 보정합니다 (4장 참고)
    const rot = page.getRotation().angle % 360;
    const box = page.getMediaBox();
    const w = rot === 90 || rot === 270 ? box.height : box.width;
    const ox = box.x, oy = box.y;

    [line1, line2].forEach((text, i) => {
      const size = 7.5;
      const tw = font.widthOfTextAtSize(text, size);
      page.drawText(text, {
        x: ox + (w - tw) / 2,
        y: oy + 18 - i * 10,   // 하단 여백 15mm 안쪽
        size, font,
        color: rgb(0.13, 0.23, 0.63),
        opacity: 0.75,
        rotate: degrees(rot),
      });
    });
  }

  // 문서 정보에도 주문번호를 남깁니다
  pdf.setProducer(`joongangart-${order.no}`);
  pdf.setCreationDate(new Date());

  return pdf.save();
}
문서 정보에도 주문번호를 남기는 이유

화면에 보이는 워터마크는 편집기로 지울 수 있습니다. PDF 문서 정보(Producer 항목)에 주문번호를 함께 넣어두면 겉으로 지워도 흔적이 남습니다. 완벽하지는 않지만 추적 가능성을 한 겹 더합니다.

인쇄할 때 찍는 것이 아니라, 내려받을 때 이미 찍혀 있어야 합니다

“인쇄하면 워터마크가 나오게” 하는 방법은 두 가지가 있는데, 둘의 안전도가 전혀 다릅니다.

브라우저 인쇄 CSS로 얹는 방식은 쓰지 않습니다. 이 방식은 인쇄 미리보기에서 머리글·바닥글을 끄거나, 개발자 도구로 해당 요소를 지우거나, PDF로 저장한 뒤 지우면 그대로 사라집니다. 즉 보호 장치가 아니라 겉모습일 뿐입니다.

서버가 PDF 파일 안에 구워 넣는 방식만 사용합니다. 내려받기 요청이 들어온 시점에 서버가 원본 PDF를 열어 모든 면 하단에 주문번호·구매자·부수를 그려 넣고, 그 결과물만 내려보냅니다. 고객이 받는 파일에는 이미 워터마크가 들어 있으므로 어떤 뷰어로 열어 인쇄해도, 파일을 그대로 전달해도 표기가 따라갑니다. 원본 PDF는 어떤 경우에도 그대로 나가지 않습니다.

시안의 인쇄하기 버튼은 이 결과물이 종이에 어떻게 나오는지 보여주기 위한 것이며, 실제 구현에서는 위 서버 처리 결과를 인쇄하는 것으로 갈음합니다.

모든 면에 찍습니다 — 1면만 찍으면 1면만 빼고 돌립니다

표지나 1면에만 워터마크를 넣으면, 2면부터 뽑아 나눠주는 것으로 간단히 우회됩니다. 면 수와 무관하게 전 면 하단에 동일한 표기를 넣습니다. 오선을 가리지 않도록 마지막 오선 아래 여백에만 그리고, 여백이 부족한 악보는 등록 단계에서 걸러 다시 받습니다(05장 등록 검사 참고).

인쇄만 허용하고 복사는 막기 선택

// qpdf로 권한 설정 — 인쇄 허용, 텍스트 추출·수정 금지
qpdf --encrypt "" "$OWNER_PW" 128 \
     --print=full --modify=none --extract=n --accessibility=y -- \

#항목내용과 대응
1페이지 회전 악보에 가로 페이지가 섞이면 /Rotate 90이 걸립니다. 좌표계가 돌아가 워터마크가 옆으로 눕거나 화면 밖으로 나갑니다. 페이지별로 회전값을 읽어 보정해야 합니다
2MediaBox 원점 모든 PDF가 (0,0)에서 시작하지 않습니다. 스캔본은 원점이 어긋난 경우가 흔해 좌표를 절대값으로 박으면 위치가 틀어집니다. getMediaBox()의 x·y를 더해 계산
3암호가 걸린 원본 로드 자체가 실패합니다. 업로드 검사에서 거부하도록 이미 기획에 반영되어 있습니다
4하단 여백 부족 여백이 15mm 미만이면 워터마크가 마지막 오선을 가립니다. 업로드 시 경고를 띄우도록 기획되어 있습니다
5스캔본 용량 300dpi 스캔은 20MB에 육박해 로드·저장에 시간과 메모리를 많이 씁니다. 업로드 상한 20MB, 최소 해상도 150dpi로 제한
6글꼴 미포함 원본 원본에 폰트가 포함되지 않으면 가사가 깨져 보입니다. 워터마크와 무관하지만 등록 시 함께 검사합니다
화면에서 멀쩡해도 인쇄하면 잘릴 수 있습니다

PDF 뷰어는 여백을 넉넉히 보여주지만 실제 프린터는 물리적 인쇄 가능 영역이 좁습니다. 반드시 종이로 출력해서 워터마크가 잘리지 않는지 확인해 주세요. A4 기준 하단 5mm 안쪽은 잘릴 수 있어, 워터마크를 하단에서 15~18pt 위에 두었습니다.
