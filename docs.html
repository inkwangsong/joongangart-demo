홈 화면과 검색

H-01
추천 검색어는 사람이 고르고, 인기 검색어는 집계합니다 추천은 “무엇을 앞에 내세울지”라는 영업 판단이고, 인기는 “고객이 무엇을 찾았는지”라는 사실입니다. 추천을 집계로 정하면 절기가 지나도 지난 검색어가 위에 남고, 인기를 손으로 고치면 더 이상 인기가 아닙니다. 둘을 섞지 않습니다.
H-02
추천 검색어에는 노출 기간을 둡니다 성탄 칸타타는 10~12월, 부활절은 2~3월처럼 기간을 정해두면 절기가 바뀔 때마다 지우고 넣을 필요가 없습니다. 기간이 비어 있으면 계속 노출합니다. 고객 화면에는 최대 9개까지 보입니다.
H-03
인기 검색어에는 제외 목록을 둡니다 자동 집계라도 오타, 시험 입력, 다른 업체 이름처럼 올라오면 안 되는 말을 내릴 방법은 있어야 합니다. 목록을 직접 고치는 대신 제외 목록에 넣어 순위에서 빼냅니다.
H-04
홈 화면의 블록은 모두 관리자에서 켜고 끌 수 있어야 합니다 메인 배너만 고정입니다. 나머지는 운영해 보고 안 쓰이면 개발 없이 끌 수 있어야 합니다. 예전에는 ‘절기로 찾기’가 메인 배너에 묶여 끌 수 없었고, ‘컬렉션’은 목록에 아예 없었습니다.
H-05
절기 이야기는 ‘이번 절기 준비’ 한 블록에서만 합니다 예전에는 절기 카드 · D-day · 베스트 절기 탭 · 성탄 컬렉션 네 블록이 성탄을 나눠 말했습니다. 지금은 남은 날짜와 중앙아트 추천(컬렉션)을 ‘이번 절기 준비’ 한 곳에 모읍니다. ‘바로 찾기’는 길만 안내하고(곡 수만 표시), 컬렉션 목록은 상단 메뉴 ‘컬렉션’에서 봅니다. 메인 배너에는 그 절기의 칸타타 곡집(예: 고난주간 「갈보리」, 부활주일 「새벽의 노래」)을 걸 수 있습니다 — 배너는 ‘무엇을 파는가’만 말하고, 남은 날짜와 추천곡은 ‘이번 절기 준비’가 맡습니다. 절기 색은 전례색을 따릅니다: 고난주간(사순절) 보라, 부활절 하늘색 · 흰색.
H-06
절기는 분류를 가로질러 찾습니다 성탄절 악보는 합창·오케스트레이션·피아노에 흩어져 있습니다. 절기로 들어오면 분류를 묻지 않고 그 절기 곡 전부를 보여줍니다. 분류 하나로 보내면 절반 이상이 빠집니다.
H-07
날짜는 화면을 여는 그 날을 기준으로 계산합니다 D-day, 남은 주 수, 집계 기준 시각을 코드에 박지 않습니다. 날짜 문자열은 한국 자정으로 읽습니다 — UTC로 읽으면 한국에서는 D-day가 하루 많게 나옵니다.
H-08
고객 화면에 나오는 정보는 모두 관리자에서 바꿀 수 있어야 합니다 코드에 박아둔 값은 개발자를 거쳐야만 바뀝니다. 악보·곡집·분류·절기·편성·반주, 사업자 정보와 결제 수단까지 관리자 화면에 편집 자리가 없는 고객 화면 정보는 두지 않습니다. 예외는 버튼 이름 같은 화면 문구뿐입니다 — 이건 운영 데이터가 아니라 제품의 일부입니다.
H-09
표지는 곡집에 붙고, 낱곡 썸네일은 곡집 표지와 악보 1면을 함께 보여줍니다 악보마다 표지를 따로 두면 같은 곡집의 곡이 서로 다른 표지로 나옵니다. 표지·소개 문구·대표곡·실물 곡집 주소는 곡집 관리에서 정하고, 악보는 수록 곡집을 고르면 표지가 따라옵니다. 반대로 낱곡 카드에 곡집 표지만 쓰면 책을 사는 것처럼 보이고 같은 곡집의 곡이 모두 같은 그림이 됩니다. 그래서 낱곡 썸네일은 곡집 표지(뒤)와 악보 1면(앞)을 겹쳐 보여줍니다 — 어느 곡집의 곡인지와 악보를 받는다는 것이 함께 보입니다. 그림 위에 「PDF」 같은 글자나 스티커는 붙이지 않습니다. 썸네일이 작은 목록(순위 · 장바구니 · 악보함 · 검색)은 악보 1면만 둡니다. 썸네일은 관리자가 따로 올리지 않습니다. 표지는 곡집의 것을, 악보 1면은 PDF를 올릴 때 미리보기 공개 면 중 첫 면을 저해상도 이미지로 자동 생성해 씁니다(미리보기 이미지와 같은 파일). 1면이 속표지·편성표인 곡은 악보 수정 > 미리보기 면에서 공개 면을 바꾸면 썸네일도 따라갑니다. PDF 변환 전이거나 실패하면 곡집 표지만 보여줘 화면이 비지 않게 합니다.
H-10
고객 화면 설명 문구는 코드표에서 나옵니다 편성(SATB → 혼성 4부 합창), 반주(오케스트라 → Full Orchestra) 같은 설명을 화면에서 조건문으로 만들지 않습니다. 분류 관리 > 편성·반주 표에 값과 설명을 함께 넣고, 새 편성을 추가할 때 설명도 같이 넣습니다.
H-11
홈의 순위는 ‘성가대가 많이 부른 곡’ 하나만 둡니다 홈 베스트는 최근 기간(기본 3개월)으로 셉니다. 예전 안에는 ‘이번 절기 준비’ 안에 지난 시즌 판매 순위(‘지난 성탄 많이 부른 곡’)를 따로 두었지만, 홈에 순위가 두 번 나오면 화면이 순위표처럼 보이고, 지휘자에게 필요한 ‘무엇을 준비할까’보다 ‘무엇이 팔렸나’가 앞서게 됩니다. 그래서 ‘이번 절기 준비’는 남은 날짜 + 중앙아트 추천만 두고, 절기 순위는 두지 않습니다. 홈 베스트에도 절기 탭을 두지 않습니다 — 절기 이야기가 두 곳에서 나오기 때문입니다(H-05).
H-12
절기 순위는 판매가 1~2년 쌓인 뒤 다시 검토합니다 오픈 첫해에는 지난 시즌 판매 기록이 없어 절기 순위를 만들 수도 없습니다. 두 번째 성탄 시즌이 지난 뒤 판매 기록을 보고, 필요하면 목록 화면(절기로 찾기)의 정렬 기준으로 넣는 쪽을 먼저 검토합니다 — 홈에 블록을 늘리지 않습니다(H-13). 그전까지 홈 편성 > 이번 절기 준비에는 순위 설정이 없습니다.
H-13
홈 블록은 지휘자가 묻는 순서대로 놓고, 블록마다 질문은 하나입니다 ① 여기는 무엇을 하는 곳인가(메인 배너) → ② 어디로 가면 되나(바로 찾기) → ③ 지금 무엇을 준비해야 하나(이번 절기 준비) → ④ 새 곡이 있나(새로 올라온 곡) → ⑤ 다른 성가대는 무엇을 부르나(많이 부른 곡) → ⑥ 아는 곡집이 있나(곡집으로 찾기). 새 곡은 자주 바뀌어 다시 오는 사람이 먼저 확인하는 칸이라 순위보다 위에 둡니다. 새 블록을 추가할 때는 어떤 질문에 답하는지부터 정하고, 이미 답하는 블록이 있으면 추가하지 않습니다. ③은 성탄 16주(부활절 14주) 전부터만 나타나므로, 비시즌 홈은 ②에서 바로 ④로 이어집니다.

메뉴 구성 (서비스 탭 · GNB · SNB)

고객 사이트 상단 메뉴도 운영 데이터입니다. 절기 · 기획전에 맞춰 바뀌므로 개발자를 거치지 않고 관리자에서 바꿉니다. 대신 화면이 깨지지 않도록 틀은 정해 둡니다.

N-01
메뉴는 ‘메뉴 구성’ 설정 하나에서 나옵니다 맨 위 서비스 탭, 상단 메뉴(GNB), 분류 화면 안의 하위 탭(SNB)을 화면 관리 > 메뉴 구성에서 정합니다. 고친 내용은 게시해야 고객 화면에 반영되고, 게시할 때마다 판 번호와 게시자 · 시각이 남아 지난 판으로 되돌릴 수 있습니다.
N-02
분류 관리는 ‘무엇으로 나누는가’, 메뉴 구성은 ‘어디에 보여주는가’입니다 분류 관리의 분류는 악보 등록의 선택지와 ‘전체 분류’ 펼침의 트리가 됩니다. 메뉴 구성은 그중 무엇을 상단에 어떤 이름 · 순서로 보일지 정합니다. 분류 관리에서 분류를 끄면 그 분류로 연결된 메뉴는 자동으로 숨겨집니다.
N-03
메뉴는 두 단계까지입니다 — GNB 아래 SNB 하위 탭 아래로 한 단계 더(3단계)는 만들지 않습니다. 휴대폰에서 세 단계 메뉴는 길을 잃게 합니다. 더 깊은 분류는 ‘전체 분류’ 펼침과 조건 검색이 맡습니다.
N-04
고정 자리가 있습니다 상단 메뉴 맨 앞 전체 분류, 맨 뒤 이용안내, 서비스 탭의 디지털 악보는 숨기거나 옮길 수 없습니다. 이용안내는 구매 전에 이용 범위를 알리는 자리라(L-08) 늘 보여야 합니다.
N-05
개수와 이름 길이에 상한을 둡니다 상단 메뉴는 고정 자리를 빼고 8개, 이름은 8자까지. 하위 탭은 분류마다 10개, 이름은 12자까지. 서비스 탭은 4개까지. PC 한 줄과 휴대폰 가로 넘김에서 읽히는 기준입니다. 넘으면 게시할 수 없습니다.
N-06
메뉴마다 ‘연결 종류’를 정하고, 종류를 더해 넓힙니다 상단 메뉴는 분류 · 절기 · 컬렉션 · 곡집 · 안내 화면 · 바깥 주소 중 하나로 연결합니다. 하위 탭은 그 분류 안에서 곡집 이름 · 편곡자 · 편성 · 절기 중 하나로 좁힙니다. 새 종류(예: 작곡가별, 영문 화면)가 필요하면 연결 종류를 하나 더하는 것으로 확장하고, 고객 화면은 모르는 종류를 그리지 않습니다 — 새 설정이 화면보다 먼저 나가도 깨지지 않게.
N-07
바깥 주소는 https만, 새 창으로 엽니다 기존 쇼핑몰 · 파트연습실처럼 다른 사이트로 가는 메뉴는 https 주소만 허용하고, 새 창으로 열며 새 창 표시를 붙입니다.
N-08
기간을 정한 메뉴는 그날 저절로 나타나고 사라집니다 · NEW는 한 번에 하나 ‘성탄 준비’처럼 절기 메뉴는 시작일 · 종료일을 넣어 예약합니다. 기간이 겹쳐 8개를 넘으면 게시할 수 없습니다. NEW 표시는 동시에 한 메뉴에만 붙입니다 — 여러 개면 아무것도 눈에 띄지 않습니다.
N-09
빈 메뉴는 보이지 않게 하고, 게시 전에 점검합니다 곡이 0곡인 하위 탭은 고객 화면에서 자동으로 숨깁니다. 게시 전 점검은 오류(개수 · 길이 · 주소 · 날짜)면 게시를 막고, 주의(꺼진 분류 연결, 빈 탭, 기간 밖, 같은 이름)는 알려만 줍니다.

3
재방문 인사 “○○님, 악보 N곡이 악보함에 있습니다” 규칙 로그인한 경우에만 노출

5

6

7
곡집으로 찾기 “아는 곡집에서 고르고 싶다” 규칙 기존 고객은 “중앙성가 52집”처럼 곡집 이름으로 기억합니다. 노출할 곡집은 관리자 → 홈 편성에서 고릅니다
순서의 원칙 — 지휘자가 사이트에 와서 하는 질문 순서입니다: 무엇을 하는 곳인가 → 어디로 가나 → 지금 무엇을 준비하나 → 남들은 무엇을 부르나 → 아는 곡집 → 새 곡. 블록마다 질문이 하나씩이고, 같은 질문에 답하는 블록은 두지 않습니다. 순서와 노출은 관리자 → 홈 편성에서 조정합니다.

01워터마크 PDF — 기본 원리

원본 PDF 위에 구매 정보를 담은 텍스트 층을 덧씌워 새 PDF를 만들어 내보냅니다. 원본 파일은 외부로 나가지 않고, 요청할 때마다 사본을 만들어 전달합니다.

02기술 선택

Next.js 환경이므로 pdf-lib를 권합니다. 순수 자바스크립트라 서버에 별도 프로그램을 설치하지 않아도 됩니다.

후보형태판단 권장
pdf-lib + @pdf-lib/fontkit순수 JS 설치 부담 없음. 서버리스에서도 동작. 한글은 폰트 임베딩 필요 채택
qpdf실행 파일 PDF 권한 설정(복사 금지·인쇄 허용)에 유용. 워터마크 후처리로 병행 가능 선택
Ghostscript실행 파일 기능은 강력하나 무겁고 라이선스(AGPL) 검토 필요 보류
외부 변환 APISaaS 원본 악보가 외부로 나갑니다. 저작물 특성상 권하지 않습니다 비권장
한글 폰트가 첫 번째 관문입니다

PDF 표준 내장 폰트로는 한글을 쓸 수 없습니다. 반드시 폰트 파일을 임베딩해야 하며, 이때 subset: true 옵션이 핵심입니다. 한글 폰트는 4~8MB인데 서브셋을 켜면 실제 사용한 글자만 넣어 30~60KB로 줄어듭니다. 이 옵션을 놓치면 악보 한 장마다 5MB가 붙습니다.

폰트 라이선스도 확인이 필요합니다. 임베딩이 허용된 폰트여야 합니다. Pretendard, 나눔고딕은 OFL 라이선스라 사용 가능합니다.

    // 페이지 회전과 원점을 반드시 보정합니다 (4장 참고)
    const rot = page.getRotation().angle % 360;
    const box = page.getMediaBox();
    const w = rot === 90 || rot === 270 ? box.height : box.width;
    const ox = box.x, oy = box.y;

    [line1, line2].forEach((text, i) => {
      const size = 7.5;
      const tw = font.widthOfTextAtSize(text, size);
      page.drawText(text, {
        x: ox + (w - tw) / 2,
        y: oy + 18 - i * 10,   // 하단 여백 15mm 안쪽
        size, font,
        color: rgb(0.13, 0.23, 0.63),
        opacity: 0.75,
        rotate: degrees(rot),
      });
    });
  }

  // 문서 정보에도 주문번호를 남깁니다
  pdf.setProducer(`joongangart-${order.no}`);
  pdf.setCreationDate(new Date());

  return pdf.save();
}
문서 정보에도 주문번호를 남기는 이유

화면에 보이는 워터마크는 편집기로 지울 수 있습니다. PDF 문서 정보(Producer 항목)에 주문번호를 함께 넣어두면 겉으로 지워도 흔적이 남습니다. 완벽하지는 않지만 추적 가능성을 한 겹 더합니다.

인쇄할 때 찍는 것이 아니라, 내려받을 때 이미 찍혀 있어야 합니다

“인쇄하면 워터마크가 나오게” 하는 방법은 두 가지가 있는데, 둘의 안전도가 전혀 다릅니다.

브라우저 인쇄 CSS로 얹는 방식은 쓰지 않습니다. 이 방식은 인쇄 미리보기에서 머리글·바닥글을 끄거나, 개발자 도구로 해당 요소를 지우거나, PDF로 저장한 뒤 지우면 그대로 사라집니다. 즉 보호 장치가 아니라 겉모습일 뿐입니다.

서버가 PDF 파일 안에 구워 넣는 방식만 사용합니다. 내려받기 요청이 들어온 시점에 서버가 원본 PDF를 열어 모든 면 하단에 주문번호·구매자·부수를 그려 넣고, 그 결과물만 내려보냅니다. 고객이 받는 파일에는 이미 워터마크가 들어 있으므로 어떤 뷰어로 열어 인쇄해도, 파일을 그대로 전달해도 표기가 따라갑니다. 원본 PDF는 어떤 경우에도 그대로 나가지 않습니다.

시안의 인쇄하기 버튼은 이 결과물이 종이에 어떻게 나오는지 보여주기 위한 것이며, 실제 구현에서는 위 서버 처리 결과를 인쇄하는 것으로 갈음합니다.

모든 면에 찍습니다 — 1면만 찍으면 1면만 빼고 돌립니다

표지나 1면에만 워터마크를 넣으면, 2면부터 뽑아 나눠주는 것으로 간단히 우회됩니다. 면 수와 무관하게 전 면 하단에 동일한 표기를 넣습니다. 오선을 가리지 않도록 마지막 오선 아래 여백에만 그리고, 여백이 부족한 악보는 등록 단계에서 걸러 다시 받습니다(05장 등록 검사 참고).

인쇄만 허용하고 복사는 막기 선택

// qpdf로 권한 설정 — 인쇄 허용, 텍스트 추출·수정 금지
qpdf --encrypt "" "$OWNER_PW" 128 \
     --print=full --modify=none --extract=n --accessibility=y -- \
     stamped.pdf protected.pdf
